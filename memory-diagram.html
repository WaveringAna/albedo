How project memory works

Two paths share the same Markdown files: a session-start read and agent-initiated reads or writes.

What the model sees

  1. New session

    Albedo includes up to 8,000 characters of memory.md in extension context, labeled as untrusted notes.

  2. Tool instructions

    The prompt describes memory.read(), append(text), save(text), journal(text), grep(term), and search(query).

  3. During a turn

    The model calls those methods through its Python tool. read() fetches the current file; the initial context snapshot does not update mid-session.

  4. Result

    Paths, matching lines, or FTS snippets return to the model as ordinary Python output. Memory is recall, not a rule source.

What the code does

  1. Resolve workspace

    The prompt loader receives the session workspace. At kernel boot, the memory plugin asks the daemon for that same path through session.cwd.

  2. Prepare prompt

    extension.gleam loads a bounded UTF-8 preview via albedo_memory.erl when the session is prepared. No file means no preview.

  3. Handle Python calls

    albedo_plugins/memory.py uses a file lock for writes. save atomically replaces the file; append and journal add text.

  4. Search on demand

    grep checks lines literally. search builds a temporary SQLite FTS5 index from Markdown paragraphs, then returns ranked snippets.

On disk

~/.albedo/memories/-Users-Regent-Developer-albedo/memory.md — curated, durable notes

~/.albedo/memories/-Users-Regent-Developer-albedo/journal/YYYY-MM-DD.md — dated entries

Required project instructions belong in AGENTS.md. Memory content can be stale; verify facts that may have changed.
